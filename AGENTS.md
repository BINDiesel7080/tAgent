# AGENTS.md — правила работы агента с проектом trading-agent

## О проекте

RL-агент управления портфелем на Мосбирже: PPO (stable-baselines3) над Gymnasium-средой
PortfolioEnv, 6 тикеров (SBER, MGNT, PLZL, NVTK, LKOH, TATN) + кэш. Задача — научиться
распределять веса так, чтобы на holdout обгонять Equal-Weight бенчмарк. Статус: baseline
v1.1 закрыт ПОБЕДОЙ на holdout, идёт итерация v1.2 (ковариационные фичи).

## Структура и пайплайн

Цепочка данных (порядок запуска строгий, каждый шаг кормит следующий):

1. `download_full_history.py` — MOEX ISS через `/candles` (включая выходные сессии!)
   -> `candles_full.csv` (колонки: date, open, high, low, close, volume, value, SECID, weekend)
2. `build_features_v4.py` -> `rl_features_v4.pkl` (3161 строк x 31 колонка),
   `rl_prices_v4.pkl` (цены со сплайсом на мосту), `rl_features_v4_ext.pkl` (21 свежая
   строка после 2026-10-02, для будущей живой проверки)
3. `build_features_v5.py` -> `rl_features_v5.pkl` (3161 строк x 49 колонок: те же 31
   легаси-колонки БАЙТ-В-БАЙТ как в v4 + 18 новых: rv20/rv60/correq20 по 6 тикерам).
   Окна считаются по доходностной серии, байт-в-байт равной {T}_returns из v4
   (вариант A, мост обнулён в обоих). Гейт корректности: `check_v5.py`
   (np.array_equal легаси + границы фолдов; exit-код 0/1).
4. `portfolio_env.py` — класс PortfolioEnv: фолды через classmethod `build_folds(index)`;
   obs_dim берётся динамически из features.shape[1] (v4 -> 38, v5 -> 56).
   ДЕФОЛТ features_path — v4, не менять: скрипты v1.2 передают v5 явно.
5. `train_ppo.py` — Optuna (VERSION v1.2, база `optuna_ppo_v1_2.db`,
   FEATURES_FILE=rl_features_v5.pkl) + финальное обучение. Класс `_Tee` имеет метод
   `isatty()` (фикс логгинга Optuna, 2026-10-27). `_OptunaProgressCallback`
   перерисовывает `plots/optuna_progress_latest.png` после каждого триала.
6. `stage2_only.py` — отдельный скрипт: берёт best_trial из базы Optuna, обучает на
   train-части holdout-фолда, прогоняет test-окно против Equal. Поиск Optuna НЕ
   запускает. Использован один раз для v1.1; для v1.2 ЗАПУСКАТЬ НЕЛЬЗЯ, пока
   не закончится итерация (holdout израсходован — см. критические правила).
7. `plot_progress.py` — ручной просмотр прогресса Optuna: график running best,
   эталонная линия v1.1 (+0.0052), топ-5 триалов. Read-only к базе
   (--db/--study; по умолчанию optuna_ppo_v1_2.db / ppo_v1.2).
8. `smoke_v1_2.py` — одноразовый смоук-тест v1.2 (уже отработал, можно удалить).

Артефакты:
- АКТИВНЫЕ: `rl_features_v5.pkl`, `optuna_ppo_v1_2.db` (идёт прогон — не трогать),
  `logs/*.log`, `plots/optuna_progress_latest.png`. Файлы цен не менялись —

- BASELINE v1.1 (эталон, не удалять): `optuna_ppo_v1_1.db`, модели

- Появятся в конце прогона v1.2: `ppo_v1.2_optuna_history.png`,

- ЛЕГАСИ, не удалять без вопроса пользователю: `rl_features_v2.pkl`,

## Конвенции, которые нельзя менять молча

- Датасет фичей: ровно 31 колонка легаси-пайплайна — `is_weekend` + на каждый тикер
  {T}_returns, {T}_atr_pct, {T}_sma_dev, {T}_vol_z, {T}_range_pct (TR через high/low/
  prev_close; SMA50; vol_z по окну 50; range = (high-low)/close*100). Формулы менять
  ТОЛЬКО по прямой просьбе пользователя.
- Нейтральные заполнения: доли/MFI -> 0.5, доходности -> 0.0; dtype float32.
- «Мост» остановки торгов 2022-03-24: доходности обнулены, цены сплайсятся фактором
  close_prev/close_gap — все последующие доходности не искажаются. Не удалять.
- Фолды (PortfolioEnv.build_folds): TRAIN_WINDOW=1200, TEST_WINDOW=100, EMBARGO=5,
  HOLDOUT_ROWS=101 (test holdout: 2026-06-16..2026-10-02), N_OPT_FOLDS=5.
  Не менять разметку, не увеличивать HOLDOUT, не «улучшать» эмбарго.
- obs_dim: в v1.1 — 31 + 7 = 38; в v1.2 — 49 + 7 = 56 (31 легаси-колонка +
  rv20/rv60/correq20 по 6 тикеров). env берёт obs_dim динамически из
  features.shape[1] — при смене файла фичей пересчёт автоматический.
  Формулы 31 легаси-колонки и 18 новых — менять только по согласованию.

- Нормализация фичей — только по train-данным текущего фолда (уже реализовано, не переделывать).
- В train_ppo: робастная метрика M = mean - 0.5*std по фолдам; случайная длина эпизода
  (30..200) и random_start_prob=0.5 — в СРЕДУ, не в гиперпараметры Optuna.
- Все прогон-скрипты (как stage2_only.py) должны писать лог в `logs\` — повторения
  «вытаскивания из консоли» не допускать.

## Критические правила (что запрещено)

- **HOLDOUT ИЗРАСХОДОВАН (2026-10-27).** Fold 5 уже использован для финальной
  валидации v1.1: любые повторные прогоны на нём превращают его в тренировочный
  материал. **Все эксперименты v1.2 валидировать ТОЛЬКО на фолдах 0-4.**
  К fold 5 приходить один раз, в самом конце итерации, с готовой версией
  (через stage2_only.py — и только после того, как Optuna остановлена и
  выбрана лучшая модель).
- Не трогать во время запущенного обучения: база Optuna текущего активного
  прогона (сейчас `optuna_ppo_v1_2.db`), `logs/*.log`, активные файлы фичей и цен
  (`rl_features_v5.pkl`, `rl_prices_v4.pkl`), файлы моделей, `plots/*.png`
  во время записи. Запущенный процесс можно прервать только по явному указанию
  пользователя.
- Не запускать второй экземпляр train_ppo параллельно — sqlite-база Optuna
  однопроцессная.
- Не менять `VERSION` в train_ppo без обсуждения с пользователем: VERSION
  управляет именем базы Optuna, смешивание триалов разных разметок фолдов
  невалидно. Сейчас VERSION = "v1.2" (база optuna_ppo_v1_2.db) — не трогать
  до окончания итерации.
- Не менять `FEATURES_FILE` и не «переключать обратно» на v4: все скрипты v1.2
  обязаны явно передавать `rl_features_v5.pkl`. Дефолт features_path в
  portfolio_env.py остаётся v4 — не «исправлять» его.
- `plot_progress.py` и `_OptunaProgressCallback` работают с базой ТОЛЬКО
  read-only (`mode=ro&uri=true`). Любые операции записи в базу Optuna —
  только из самого train_ppo.
- Не заменять обращения `PortfolioEnv.FOLDS` — этого атрибута больше нет, есть
  `env.folds` / `get_folds()` (кэш в train_ppo).
- Не переписывать код «под красивее»: рефакторинг — только по запросу,
  с сохранением вычислительной эквивалентности (сравнение результатов
  на фиксированном сиде).
- Не создавать новые pkl/csv с похожими именами (`rl_features_v6.pkl` и т.п.)
  без прямого задания — легко запутать пайплайн.

## Стиль работы

- Все скрипты запускаются в conda-окружении `trading-agent` (Windows, cmd).
- Логировать изменения в коде честно: версия в шапке файла + список изменений.
- Если предложение меняет формулы фичей, разметку фолдов, holdout или награду среды —
  сначала вопрос пользователю, а не самовольная правка.
- Пользователь общается с Алисой (assistant) по архитектурным решениям; агент — руки
  для правок. Не игнорировать уже принятые решения, зафиксированные в этом файле.
- Запуск скриптов: пользователь запускает из терминала с уже активированным
  окружением — plain `python script.py`. Кодинг-агент (Zoo) запускает скрипты
  только с явной активацией:
  call F:\anaconda3\condabin\conda.bat activate trading-agent && python <script.py>
  (прямой вызов python.exe без activate ломает LAPACK — нативный краш, не
  перехватывается try/except; проверено 2026-10-28).
- Графики прогресса: plots/optuna_progress_latest.png перерисовывается callback'ом
  после каждого триала (train_ppo.py, _OptunaProgressCallback); ручной просмотр —
  plot_progress.py (read-only к базе). Все графические скрипты требуют
  активированного окружения.
