# Архитектура живого контура (слоистая: L0–L6 + конфиг C)


Статус: СОГЛАСОВАНА в диалоге с пользователем 2026-10-30.
Источник истины для всех слоёв и их прав. Декомпозиция ещё не начата.

## Карта слоёв

    L6  Планировщик/мониторинг  — «когда» и «что показать». ТУПОЙ: запускает
                                 пайплайн по расписанию, пересылает результаты
                                 L5. Запрет: никакой бизнес-логики, никаких
                                 «если дата такая-то». Пороги и эмбарго — в C.
    L5  Учёт и метрики          — эквити, maxDD, сравнение с Equal, kill-switch.
    L4  Брокерский адаптер      — ЕДИНСТВЕННОЕ место, где живёт «БКС»
                                 (API, тарифы, лоты, расчёты). Сначала эмуляция,
                                 потом реальный адаптер БКС один-в-один.
    L3  Портфельная политика    — целевые веса -> ордера: лоты, гистерезис,
                                 парковка кэша (ТЗ parking_exp_v0.1).
                                 Тестируется на фолдах 0-4 БЕЗ брокера.
    L2  Модель/агент            — obs -> целевые веса (v1.2, v1.3, ансамбль).
                                 Никогда не знает про лоты, комиссии, брокера.
    L1  Фичи                    — свечи -> матрица признаков. Единый код для
                                 бэктеста и live + гейт байт-в-байт
                                 (check_live_gate.py). ПЕРВЫЙ блок декомпозиции.
    L0  Данные                  — MOEX ISS, календарь, свечи, докачка.
    C   Конфигурация            — ОДИН файл: тикеры, тарифы, пороги, VERSION,
                                 источник ставки фонда, комиссия парковки.
                                 Читают все слои; слои НЕ хранят своё значение.

## Правила зависимостей (две, без исключений)

1. Каждый слой смотрит ТОЛЬКО вниз. Перескакивание через слой — ошибка.
2. Вся вариативность (брокер, фонд, тикеры, тариф, пороги) — в C.

## Контракты стыков (гарантия слоёности)

- L2 -> L3: «на дату T целевые доли: 6 тикеров + кэш, сумма 1».
- L3 -> L4: «список ордеров: тикер, сторона, лоты» + «запрос: позиции/остаток».
- L4 -> L5: события «исполнено по цене X, комиссия Y».
- L1 -> L2: матрица признаков фиксированной ширины (49 + веса = 56).

## Тест слоёности (критерий: минимизация распространения правок)

| Событие                              | Меняется        | НЕ меняется              |
|--------------------------------------|-----------------|--------------------------|
| Смена брокера                        | L4 + строка в C | агент, фичи, политика, учёт |
| Смена фонда парковки (SBMM -> иная)  | C (одна строка) | всё остальное            |
| v1.2 -> v1.3                         | L2 + VERSION в C| исполнение, брокер, учёт |
| Добавление тикера                    | L0, L1, C       | L3, L4                   |
| Пересборка фичей (v5 -> v6)          | L1 + гейт       | L3, L4 (модель переобучается) |

Контрольный ритуал при любой правке: «в скольких слоях дифф?» —
«в одном + конфиг» = ок; «в двух и больше» = стоп, подумать.

## Известные долги и точки расширения

- D4 (функционал исполнения) слит: расщепить на L3 (политика парковки/
  гистерезис/лоты) + L4 (эмуляция счёта). Статус: не начато.
- COMMISSION_RATE — атрибут класса PortfolioEnv (portfolio_env.py:33),
  снаружи не переопределяется. Отдельная конфигурируемая комиссия для
  парковки — потенциальная правка L2; закладывать осознанно, не патчить.
- Факты для L4: комиссия среды 0.0004/оборот (portfolio_env.py:33);
  кэш в среде исключён из turnover (portfolio_env.py:319-322) — затраты
  парковки в живом контуре добавятся сверх того, что «видел» агент.
