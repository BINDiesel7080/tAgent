# trading-agent

RL-агент управления портфелем на Московской бирже: PPO (stable-baselines3) над
Gymnasium-средой `PortfolioEnv`, 6 тикеров (SBER, MGNT, PLZL, NVTK, LKOH, TATN)
плюс денежная позиция. Задача — распределять веса так, чтобы на holdout
обгонять Equal-Weight бенчмарк, лучше контролируя просадку.

## Пайплайн

Порядок запуска строгий, каждый шаг кормит следующий:

```
download_full_history.py            -> candles_full.csv (MOEX ISS /candles)
  -> build_features_v4.py / build_features_v5.py  -> rl_features_v4.pkl / rl_features_v5.pkl
  -> check_v5.py                    -> гейт корректности (exit-код 0/1)
  -> train_ppo.py                   -> Optuna (поиск) + финальное обучение
```

`stage2_only.py` запускается только по окончании итерации — он расходует
holdout.

## Результат baseline v1.1

На holdout: **PPO −5.82% против Equal-Weight −10.91%** (+5.09 п.п.),
**все 7 сидов выше Equal**.

## Структура репозитория

- корень — активный код и текущие артефакты (включая исторические `.txt`-дампы
  `portfolio_env.txt` и `train_ppo.txt`, попавшие в индекс раньше правил игнорирования);
- `v0.5`–`v1.1/` — исторические снапшоты версий кода;
- `back/` — ранняя история (v0.1–v0.6): `.py`-исходники и 8 унаследованных
  `.txt`-копий, уже отслеживаемых git (правило `!/back/*.py` новые `.txt` не пустит);
- `docs/` — документы по экспериментам (`ab_v3_vs_v2.md` — копия лога A/B);
- `plans/` — планы итераций;
- `AGENTS.md` — правила работы агента с проектом.

## Окружение

conda-окружение `trading-agent`, версии зависимостей запиннены в `requirements.txt`.

## Ограничение

Holdout fold 5 израсходован (финальная валидация v1.1): повторные прогоны на нём
невалидны, эксперименты ведутся только на фолдах 0–4.
